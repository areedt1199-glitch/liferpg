# liferpg — แผนผลิตภัณฑ์

## สถานะล่าสุด — ขั้นที่ 7
ตรวจระบบเดิมและแก้ timeout ของ account fetch (15 วินาที) กับปุ่มเริ่มเควสต์ระหว่างบันทึก ไม่เพิ่มฟีเจอร์เกมหรือเปลี่ยนธีม Demo ตรวจครบ 5 ด่านผ่าน production browser และ UI จริงสามขนาด พร้อมสาธิต บัญชีจริงเชื่อม Supabase และมีหลักฐานขั้น6หนึ่งบัญชี แต่ยังไม่ผ่าน live suite สองบัญชี/ข้าม session ครบชุด เพราะไม่มีบัญชีทดสอบใหม่ จึงยังไม่รับรองการเปิดใช้งานทั่วไป ดู verification และ mvp-demo-guide เป็นสถานะปัจจุบัน เนื้อหาขั้น1–6ด้านล่างเป็นประวัติการพัฒนา ไม่ใช่ข้อจำกัดปัจจุบันทุกข้อ ไม่มี push/deploy

## แนวคิด
เว็บพัฒนาชีวิตจริงในรูปแบบ RPG รองรับคอมพิวเตอร์และมือถือ ผู้ใช้ตั้งเป้าหมาย ทำเควสต์ย่อย แล้วได้รับ XP เหรียญ และปลดล็อกช่องถัดไป ตัวละครเดินบนแผนที่คดเคี้ยวเป็นช่องคล้ายบอร์ดเกม ใช้ภาพ ตัวละคร ข้อความ และ UI ของ liferpg เอง ไม่คัดลอกโลโก้หรือ assets จากแอปอ้างอิง

## ประสบการณ์หลัก
วันนี้ → เลือกเป้าหมาย → เปิดแผนที่ → เข้าเควสต์ปัจจุบัน → โฟกัสทำ → ยืนยันสำเร็จ → รับรางวัล → ตัวละครเดินไปช่องถัดไป

## การประยุกต์แอปอ้างอิง
- Duolingo: เส้นทางเป็นจุดตามลำดับ แยกด่านปัจจุบัน ด่านที่ผ่านแล้ว และด่านที่ล็อก
- Habitica: ภารกิจในชีวิตจริงให้ XP เหรียญ เลเวล และอุปกรณ์ตัวละคร
- Forest: ฉากระหว่างโฟกัสแสดงความคืบหน้าตามเวลา เช่น ต้นไม้เติบโตหรือคริสตัลสว่าง

## โครงสร้างและขอบเขตโค้ด
เป้าหมาย → แผนที่ → เควสต์ → ขั้นตอนย่อย แต่ละเควสต์มีเงื่อนไขสำเร็จและรางวัล แผนที่ควบคุมลำดับการปลดล็อก

ขั้นที่ 1 ตั้งฐาน routes, app shell, UI ที่ใช้ร่วมกัน และ CSS placeholders แล้ว

ขั้นที่ 2 พัฒนา UI วันนี้ เป้าหมาย แผนที่ รายละเอียดเควสต์ และโฟกัส ใช้ fixture ชุดเดียวใน `src/features/journey/fixtures.ts` แสดงชื่อเป้าหมาย “สร้างเกมแรก” พร้อม 5 ด่าน โดยด่าน 1 ผ่านแล้ว ด่าน 2 ปัจจุบัน ด่าน 3–5 ล็อก ข้อมูลนี้ถูกนำมาใช้สำหรับการออกแบบตามคำขอขั้นที่ 2 เท่านั้น ไม่ใช่การพัฒนาระบบความก้าวหน้าของขั้นที่ 3

เพิ่ม `src/features/quests`, `journey`, `focus`, `character` ตามส่วนที่ใช้จริง แยก types/fixture ออกจาก UI ไม่สร้างบริการฐานข้อมูลล่วงหน้า สถานะเปลี่ยนได้เฉพาะจุดที่เลือกอ่านบนแผนที่ ไม่เปลี่ยนสถานะเควสต์หรือบันทึกข้อมูล ส่วน focus ตรวจ fixture ฝั่ง route เพื่อป้องกันการเข้า URL ด่านล็อกโดยตรง

เมื่อเพิ่มระบบจริง ให้วางกฎเกมและฟังก์ชันเข้าถึงข้อมูลแยกจาก UI เพื่อเปลี่ยนจาก fixture เป็นฐานข้อมูลจริงได้ `src/lib` จะเพิ่มเมื่อมี utility หรือ integration ที่ใช้จริง ไม่สร้างชั้น abstraction ล่วงหน้า

## กฎผลิตภัณฑ์
- ผู้ใช้โฟกัสทีละเควสต์
- แต่ละเควสต์มีเป้าหมาย ขั้นตอนย่อย และเงื่อนไขสำเร็จชัดเจน
- เริ่ม พัก และกลับมาทำต่อได้
- เวลาครบไม่ถือว่าเควสต์สำเร็จโดยอัตโนมัติ ต้องยืนยันความสำเร็จ
- เมื่อสำเร็จให้เลือกทำเควสต์ถัดไปหรือพัก ไม่เริ่มงานใหม่อัตโนมัติ
- ไม่ลดความก้าวหน้าเพราะขาดไปหนึ่งวัน
- แยกงานทำซ้ำรายวันกับด่านที่ผ่านครั้งเดียว
- แต่ละด่านรับรางวัลได้ครั้งเดียว ส่วนงานทำซ้ำรับได้ครั้งเดียวต่อรอบที่กำหนด
- เมื่อเชื่อมฐานข้อมูลจริง ต้องตรวจสิทธิ์ การผ่านด่าน และการให้รางวัลฝั่งเซิร์ฟเวอร์

กฎเหล่านี้เป็นข้อกำหนดสำหรับขั้นต่อไป ขั้นที่ 2 ยังไม่ได้พัฒนาระบบเกม ตัวจับเวลา การผ่านด่าน รางวัล หรือ persistence หน้าโฟกัสแสดงภาพนิ่งและระบุว่าจะเปิดตัวจับเวลาในขั้นถัดไป

## แผนขั้นต่อไป
2. เสร็จแล้ว: ออกแบบและพัฒนา UI หน้าวันนี้ แผนที่ และโฟกัสใน Next.js พร้อม fixture 5 ด่านสำหรับออกแบบ ไม่ได้สร้างไฟล์ Figma
3. เสร็จแล้ว: แยก definitions ออกจาก UserProgress เลือกเป้าหมาย เริ่มเควสต์ ทำต่อ และบันทึก localStorage ผู้ใช้ใหม่ด่าน 1 available ด่าน 2–5 locked ไม่มี completed เปลี่ยน available → in_progress ได้ครั้งละหนึ่งเควสต์ เปิด focus ตรงต้องเป็น active quest กำลังทำ ไม่มีการปลดล็อกหรือผ่านด่าน
4. เสร็จแล้ว: checklist ด้วย step ID คงที่ ตัวจับเวลา timestamp พร้อมพัก/ทำต่อและรอบใหม่ บันทึกใน progress schema 2 เดิม พร้อม migration จาก schema 1
5. เสร็จแล้ว: ยืนยันผ่านเควสต์ รับรางวัล XP/เหรียญ/เลเวล เปิดด่านถัดไปและจบเป้าหมาย ใน snapshot schema 3 เดิม
6. เตรียมโค้ดบัญชี Supabase SSR, schema/RLS/grants และ transaction รับรางวัลแล้ว ยังต้องตั้งค่าโปรเจกต์และตรวจ integration จริงก่อนถือว่าเชื่อมใช้งานได้
7. ทดสอบวงจรทั้งหมดบนมือถือและ desktop

ร้านค้า อุปกรณ์ บอส Skill Tree และ 3D อยู่หลังต้นแบบหลัก เลือก Supabase ในขั้นที่ 6 แล้ว แต่ยังไม่ได้เชื่อม remote

## ประวัติหลังขั้นที่ 3
เนื้อหาเส้นทางอยู่ใน definitions.ts ไม่มีสถานะผู้ใช้ Progress อยู่ใน progress.ts และ progress-store.ts แยกกฎเลือกเป้าหมาย เริ่มเควสต์ และสิทธิ์เข้า focus ออกจาก UI สถานะ completed เป็นชนิดข้อมูลสำหรับอนาคต validation ใน schema ขั้นนี้ยอมรับเฉพาะสถานะที่เข้าถึงได้จริง จึงไม่ย้าย fixture เดิมที่ผ่านแล้ว 1/5 มาเป็น progress

ข้อมูลในเครื่องใช้ version 1 และ key liferpg.progress.v1 เมื่อข้อมูลไม่รองรับไม่เขียนทับ และเมื่อบันทึกไม่สำเร็จไม่เข้าสู่ focus เป็น persistence ของต้นแบบ ไม่มีบัญชีหรือ server authorization ตัวจับเวลา/ฉาก focus ยังเป็นภาพนิ่ง รางวัลเป็นแผน ยังไม่มี XP เหรียญ เลเวลอัป การผ่านด่าน หรือปลดล็อกด่านถัดไป


## ประวัติหลังขั้นที่ 4
ใช้ progress/store ชุดเดิม เพิ่ม focus รายเควสต์และ checklist stable IDs schema 2 อ่านข้อมูล schema 1 แล้วเติมค่าเริ่มต้นโดยไม่ล้าง active quest กฎเวลาอยู่ใน src/features/focus/rules.ts กฎแก้ checklist/timer ตรวจ canFocus ก่อนทุก mutation ป้องกันด่านล็อก/ยังไม่เริ่ม

รอบ idle/running/paused/finished อิง timestamp และยอดเวลา commit ทุกการเปลี่ยนสถานะ จบรอบหนึ่งครั้งและคำนวณ capped delta เมื่อกลับจากปิดหน้า ไม่มี storage writes ทุกวินาที Web Locks serialize การเขียนข้ามแท็บ ส่วน storage event ซิงก์ UI เริ่มรอบใหม่ต้องกดเองและคง checklist/เวลาสะสม

เช็กครบหรือเวลาครบไม่ถือว่าผ่านเควสต์ ยังไม่เพิ่มการปลดล็อก XP เหรียญ หรือเลเวลอัป กฎยืนยันสำเร็จและรางวัลอยู่ขั้นที่ 5 ต่อไป

## ประวัติหลังขั้นที่ 5
ทำวงจรครบ 5 ด่านด้วยการยืนยันงานด้วยตนเองหลัง checklist ครบ ไม่ต้องรอ timer รางวัลและ completedAt อยู่ใน record keyed by quest ID พร้อมยอด totalXP/coins และ goalCompletedAt ใน progress snapshot เดียว ใช้ Web Lock/read ล่าสุดก่อนทุก mutation completed รับซ้ำไม่ได้ ปิดเวลาที่ใช้จริงโดยไม่เติมให้ครบระยะเวลาแนะนำ

รางวัลใช้ definitions เดิม ไม่เพิ่มโบนัสเป้าหมายหรือร้านค้า เมื่อสำเร็จแสดงผลและเลเวลที่เปลี่ยนจริง แล้วเลือกเปิดรายละเอียดถัดไปหรือพัก ไม่เริ่มงานเอง หน้า character/today/goals/map ใช้สถานะจริง schema 1/2 เติมยอดเป็นศูนย์โดยรักษา active/checklist/เวลาเดิม ภาพเดินเป็น animation สั้นตอนตัวละครมาถึงด่าน ไม่เป็นเงื่อนไขบันทึก รองรับ reduced-motion

หยุดก่อนขั้นที่ 6 ยังไม่มีบัญชี ฐานข้อมูล หรือการตรวจรางวัล server ข้อมูล localStorage ผู้ใช้แก้เองได้ ไม่มี push/deploy

## สถานะล่าสุด — ขั้นที่ 6
โหมดบัญชีเป็นค่าเริ่มต้น แต่ไม่มี environment จึงแสดงสถานะยังไม่ได้ตั้งค่าฐานข้อมูล เก็บ demo เดิมแยกและเปิดด้วยตนเอง ไม่รวมยอดในบัญชี โค้ด signup/login/logout/edit name ใช้ verified server user และ cookies refresh ตาม Next.js Proxy รุ่นติดตั้ง

บัญชีโหลดความก้าวหน้าผ่าน RPC ที่ตรวจ auth.uid() และล็อก user_progress แถวเดียวต่อผู้ใช้ ทุก completion ตรวจลำดับ/active/checklist ใช้ reward definitions ใน DB ปิดเวลา server และเขียน completed/ledger/unlock/goal transaction เดียว unique ledger ป้องกันรับซ้ำ ยอดจาก sum ledger เท่านั้น ใช้ revision กัน response เก่าทับใหม่ และล้าง account view เมื่อ auth/โหมดเปลี่ยน

RLS ทุกตาราง public, อ่านของตัวเอง, แก้ได้เฉพาะชื่อตัวละครโดยตรง กฎ progress เขียนผ่าน entrypoint ที่จำกัด grants/search_path helper เรียกตรงไม่ได้ ไม่ใช้ service role หรือ metadata สำหรับสิทธิ์ ไม่มี database writes ทุกวินาที BroadcastChannel ซิงก์ browser เดียว และ refetch ตอนกลับแท็บ/เปิดหน้า; ไม่เพิ่ม Realtime ต่อเนื่องข้ามอุปกรณ์

migration/seed พร้อมและตรวจด้วย PGlite แต่ยังไม่ใช่ Supabase integration ไม่มี remote mutation/advisor run รอระบุโปรเจกต์ที่เป็น liferpg และตั้ง environment ตาม supabase-setup.md แล้วใช้บัญชีทดสอบตรวจ Auth/Data API/concurrent RPC จริงก่อนขั้นที่ 7 ไม่เพิ่มร้านค้า บอส 3D หรือสังคม

อัปเดต remote: ผู้ใช้สร้าง liferpg ynxtoynvjgvxulvxxmxn ลง schema/definitions/seed และ indexes ตาม advisors แล้ว ตั้ง Auth URL3010 ตรวจ Email enabled/confirm true ยังไม่มี .env.local จึงยังไม่ทดสอบบัญชีจริง/live integration ไม่ถือว่าแอปเชื่อมสำเร็จ ดู verification ล่าสุด

Configuration ล่าสุด: ผู้ใช้ตั้ง .env.local แล้ว ตรวจ Auth endpoint200/anonymous401, build และหน้าprofileจริงพร้อมสมัคร ยังรอผู้ใช้กรอกบัญชีทดสอบและยืนยันอีเมล ไม่ถือว่า flowบัญชี/live integrationผ่านก่อนตรวจจริง

ผลบัญชีจริงล่าสุด: ตรวจด่าน1ครบวงจร ledger1/XP120/coins35/nextavailable และlogoutล้าง2แท็บแล้ว แก้JSON key ordering validation และbroadcastหลังidentityเปลี่ยน ยังรอfresh test accounts2บัญชีสำหรับlive suite/A-B isolation ไม่เริ่ม7
ปรับหน้าสมัครในขั้น6: แยกตัวเลือกจาก login เพิ่มยืนยันรหัสผ่านและแสดง/ซ่อนรหัส ตรวจทั้ง client/server ไม่เปลี่ยนระบบ progress หรือเริ่มขั้น7
